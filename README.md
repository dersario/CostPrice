# Себестоимость продуктов и рецептов

Локальное PWA для ведения справочника ингредиентов и расчёта стоимости рецептов. Основные данные хранятся в IndexedDB через Dexie; приложение не требует аккаунта и работает офлайн после первого успешного открытия. Синхронизация через Supabase необязательна.

## Запуск локально

Требуется Node.js 20.19+ или 22.12+ и npm.

```bash
npm install
cp .env.example .env
npm run dev
```

Для локального использования без облака значения Supabase можно не задавать: ингредиенты, продукты, рецепты и затраты останутся в браузере.

## Настройка Supabase

1. Создайте проект Supabase.
2. Откройте SQL Editor и выполните содержимое [`supabase/schema.sql`](./supabase/schema.sql).
3. Скопируйте Project URL и публичный `anon` key в `.env`:

   ```dotenv
   VITE_SUPABASE_URL=https://your-project.supabase.co
   VITE_SUPABASE_ANON_KEY=your-public-anon-key
   ```

4. Перезапустите Vite. В приложении откройте «Настройки», задайте код рабочей области и нажмите «Подключиться».
5. На других устройствах используйте тот же код и URL/key проекта. Пока сеть недоступна, локальные изменения остаются в очереди; при восстановлении соединения синхронизация запускается автоматически.

Клиент использует только Supabase anon key и не вызывает Supabase Auth. Никогда не помещайте `service_role` key в браузерный `.env` или исходный код. Переменные `VITE_*` встраиваются в клиентский bundle и доступны пользователям.

Синхронизируются только таблицы `ingredients`, `products`, `recipe_items` и `direct_costs`. В приложение не добавлены email, имя пользователя, пароль, `user_id`, аналитика или телеметрия. Код рабочей области хранится в `localStorage`; в облако передаётся только его SHA-256 идентификатор. Удаления передаются как tombstone-записи, а более новая версия определяется по `updated_at`.

### Важное предупреждение о безопасности

Код рабочей области и его SHA-256 хеш **не являются аутентификацией или контролем доступа**. Пространство имён длиной 32 hex-символа помогает устройствам выбрать общий набор записей, но не мешает обладателю Project URL и anon key обращаться к данным напрямую. В схеме намеренно нет RLS-политик, а anon key имеет права чтения и записи всех четырёх таблиц.

Это приемлемо для личного/семейного использования, для публичного сервиса нужна настоящая аутентификация. Не храните в таком проекте секретные или чувствительные данные и не публикуйте рабочую область как защищённый ресурс.

## Расчёты

- Цена ингредиента задана за выбранную единицу закупки.
- В каждой строке рецепта количество и единица задаются явно; масса конвертируется между g/kg, объём — между ml/l. Перевод между разными измерениями запрещён.
- Полная себестоимость — материалы + труд + накладные; себестоимость на единицу — итог, делённый на положительное количество выхода.
- Изменение единицы измерения ингредиента на другой тип заблокировано, если это сделает существующие строки рецептов несовместимыми.

## PWA и публикация

В `vite.config.ts` настроен `vite-plugin-pwa` с `generateSW`, precache статики и автоматическим обновлением Service Worker. Манифест находится в `public/manifest.json`; SVG-иконки в `public/icons/` являются заглушками и могут быть заменены.

```bash
npm run build
npm run preview
```

Для публикации загрузите содержимое `dist/` на HTTPS-хостинг статических сайтов с fallback для навигации SPA на `index.html`. Service Worker и Web Crypto требуют безопасного контекста (HTTPS; `localhost` подходит для разработки). Офлайн-режим становится доступен после первого онлайн-визита, когда Service Worker успеет закэшировать файлы приложения.
